## 核心设计

FileAccess 的中心是“我的远端空间”，本机文件主要作为上传来源、备份来源和离线副本。初期不建设完整的本机文件管理器。

应用只连接用户配置的服务；无广告、无订阅依赖、无默认遥测，不要求额外注册 FileAccess 账号。协议实现编译进应用，通过接口替换和增加，不引入下载执行插件。

四种协议全部纳入架构和产品范围，但具体能力由服务端、账号权限和加密状态共同决定。UI 不能因为连接类型叫 S3 或 WebDAV 就假定一定支持恢复、原子移动或断点上传。

照片自动上传默认使用“备份”语义：新增文件上传；修改保留新版本或另一副本；本机删除不传播到远端。双向同步作为独立模式，在冲突与删除保护成熟后启用。

端到端加密第一阶段限定为私有网盘的独立加密空间。架构从首日保留入口，但加密格式、恢复机制和跨客户端一致性验证通过前，不向用户宣称支持 E2EE。

## 默认假设与待确认

| 项目 | 本版采用的默认值 | 何时需要确定 |
| --- | --- | --- |
| 首批设备 | Android 15+，手机优先，兼容平板/折叠屏 | M0；若要支持旧设备再调整 minSdk 和测试矩阵 |
| 开发优先级 | 用户最新确认：首版只支持 SMB；随后按需要扩展其他协议 | 先完成 SMB 纵向流程 |
| NAS 条件 | SMB2/3，用户手动配置主机、共享和账号；不依赖 NAS 型号 | 用户实际 NAS 联调时在 App 中输入；不在文档保存凭据 |
| 私有网盘 | 用户确认已有 API / 加密方案，资料将后续提供 | 后续对接；03 只定义应用侧能力映射清单，不另定后端协议 |
| 同步模式 | 先单向备份，后双向同步 | 可在产品评审调整 |
| 加密范围 | 私有网盘专用空间；对齐已有方案，完整恢复演练后上线 | 私有协议阶段；NAS 首版不依赖该资料 |
| 发布 | 先个人安装和真机验证 | 对外发布前另行确定分发方式 |

若私有网盘已存在 API 或 E2EE 格式，以兼容现有服务为优先，保留应用层能力边界，不强迫后端采用文档中的 URL 或字段命名。
