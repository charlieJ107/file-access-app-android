# 07 实施计划与验收

## 交付策略

用户已确认首版为 NAS（SMB / WebDAV），S3 和已有私有网盘后续接入。每一阶段先完成可运行的纵向流程，再扩大操作范围；不先一次性生成全部模块空壳。私有 API 文档未就绪不阻塞 NAS 开发。

本轮只完成设计。下面的构建命令、测试与基准是后续执行计划，不代表已经运行。

## M0 的具体工作

1. 保留当前包名和 minSdk 35，确认目标设备与 API 37 的 SDK 可用性；初始化版本控制作为后续实施步骤。
2. 记录现有 AGP 9.4.0、Gradle 9.6.0、daemon JDK 25 配置；核对本机 Gradle JDK。Java/Kotlin 编译目标统一为 17。需要更换运行 JDK 时记录兼容依据。
3. 启用 Compose compiler，使用稳定 Compose BOM；AGP 9 内置 Kotlin 下不重复套用旧 Kotlin Android 插件。固定 Hilt/KSP/Room3 编译组合。
4. 新增最小 Application、Activity、导航状态与一个可预览屏幕；实现 FakeStorageProvider，测试 UI 与 SDK 隔离。
5. 在用户指定的测试共享/目录运行 DAV、SMB 最小连接/列表/范围读取/上传验证，先用生成的非私人样本。
6. 测试 Android 17 的局域网权限拒绝/授权和无公网 Wi-Fi；测试 WorkManager 自动唤起、UIDT 手动传输、进程中断后的恢复入口。
7. 测试媒体完整/部分授权和 URI 持久化，明确哪些来源能获得原片；列出 SAF 目录访问限制。
8. 修订能力报告和 ADR 后进入真实管理功能。除这些高风险点，不为模板样例添加无意义测试。

## 测试分层和环境

纯 Kotlin 单元测试覆盖同步判定、冲突策略、任务状态机、去重、条件写计划和错误分类。使用可注入时钟/随机源，测试重试与租约边界；属性测试关注“未知状态不能触发删除”和“重复执行不改变已提交结果”。

Adapter 契约测试在受控服务上验证，Fake 不能替代网络集成。HTTP 使用可控响应模拟超时/部分读取；真实 WebDAV 测试常见 NAS 服务；SMB 用 Samba 和目标 NAS；S3 后续用真实兼容 endpoint 及必要的 AWS 测试范围。记录服务版本、启用扩展和账号权限。

Android 测试覆盖 WorkManager、JobService、MediaStore、SAF、Keystore、通知和 UI。至少一台真实目标手机测试后台行为、SMB 性能和硬件密钥；模拟器只覆盖系统组合，不能代替 OEM 后台限制测试。

基准用专用非私人数据集，包含空文件、1 byte、分片边界前后、未知长度流、4 GiB 以上文件、20 GiB 大视频、Unicode/保留字符名称以及 10 万条目录。仅在明确测试根下写入和清理，不能拿用户真实相册做破坏性测试。

## 构建与发布门槛

实施后的基础检查可从以下命令开始（当前设计阶段未运行）：

```powershell
.\gradlew.bat --version
.\gradlew.bat :app:assembleDebug :app:lintDebug :app:testDebugUnitTest
.\gradlew.bat :app:connectedDebugAndroidTest
.\gradlew.bat :app:assembleRelease
```

模块拆分后把各 JVM/Android library 的单测和 lint 加入 CI，导出并版本化 Room schema；不能只跑 app 的模板测试后宣称业务通过。

release 启用并验证 R8/资源收缩，保留必要的协议 SDK 配置；私有签名密钥不提交仓库。维护依赖锁定/校验、第三方许可清单、去敏诊断和更新日志。NAS v1.0 发布要求 T01–T13 的相关路径通过，尚未实现的协议与安全能力不能宣传已支持。
